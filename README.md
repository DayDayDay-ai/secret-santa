# Тайный Санта — 6 участников

## Бесплатное размещение (Vercel Hobby + Supabase Free)
1. Создайте бота через https://t.me/BotFather командой `/newbot`. Сохраните токен приватно.
2. Создайте проект https://supabase.com/dashboard. В SQL Editor выполните `schema.sql`, затем `migration-v2.sql`. В настройках API найдите Project URL и legacy service_role key (не anon).
3. Загрузите файлы этого архива в **приватный** репозиторий GitHub. Импортируйте его в https://vercel.com/new. Framework Preset: Other, без build command, output directory по умолчанию (корень). Node 22. Добавьте переменные окружения из `.env.example` в Settings → Environment Variables. APP_URL — HTTPS адрес вашего проекта без завершающего слеша. ADMIN_ID сначала можно оставить пустым. Секреты генерируйте независимо (например `openssl rand -hex 32`). Deploy / Redeploy после изменения переменных.
4. В терминале выполните (подставьте значения; не публикуйте историю команды):
```sh
curl -X POST "https://api.telegram.org/bot$BOT_TOKEN/setWebhook" -H 'Content-Type: application/json' -d "{\"url\":\"$APP_URL/api/bot\",\"secret_token\":\"$WEBHOOK_SECRET\"}"
```
Переменные shell BOT_TOKEN, APP_URL, WEBHOOK_SECRET должны быть предварительно заданы. Можно также настроить кнопку меню через BotFather → /setmenubutton, указав APP_URL.
5. Напишите боту /start. Он сообщит ваш Telegram ID; внесите его в ADMIN_ID в Vercel и повторно разверните. Откройте бота, выберите Ильхам, введите Ильхам, откройте Настройки и назначьте дату.
6. Для автоматического запуска каждую минуту включите Supabase Cron и pg_net (Dashboard → Integrations). В SQL Editor выполните запрос ниже, заменив адрес и секрет. Лучше использовать Vault для хранения секрета, если база используется другими администраторами.
```sql
select cron.schedule('santa-tick', '* * * * *', $$
  select net.http_post(url := 'https://YOUR-PROJECT.vercel.app/api/tick', headers := '{"Authorization":"Bearer YOUR_CRON_SECRET","Content-Type":"application/json"}'::jsonb, body := '{}'::jsonb);
$$);
```
Проверьте Cron job runs. Без Cron жеребьёвка срабатывает при первом входе после даты, но автоматическое сообщение требует Cron. Бесплатный Supabase может приостанавливаться при низкой активности; проверьте проект перед датой. Уведомления отправляются всем, кто открыл /start. Повторная доставка возможна при параллельном запуске или сбое между отправкой и сохранением.

## Проверка
`npm test` — тесты жеребьёвки, приватности ответа API, даты и HMAC Telegram. Проверьте реальную интеграцию с двумя или шестью тестовыми аккаунтами до мероприятия.

## Редактирование
`index.html` — весь дизайн и интерфейс; `api/index.mjs` — команды и доступ; `api/core.mjs` — жеребьёвка и авторизация; `schema.sql` — исходные имена и пары (менять до регистрации). После изменения файлов push в GitHub вызовет новый deploy. Данные не удаляются при новом deploy.

## Особенности и ограничения
- Имя подтверждает выбор, но не личность: любой знающий имя может занять свободный профиль. Администратор может снять привязку профиля до или после жеребьёвки; при повторной регистрации сохраняются желания и назначение. Разошлите ссылку только своим. Для строгой проверки добавьте одноразовые персональные коды.
- Администратор в приложении не видит чужие списки или распределение; как участник видит собственные желания и назначенного получателя. Владелец Supabase/Vercel с доступом к базе или серверным секретам технически может увидеть данные. Это не сквозное шифрование.
- После раскрытия дата и первое распределение фиксируются. Сброс профиля снимает только привязку Telegram. Лимит 10 подарков на человека, фото сжимается в браузере и хранится в базе. Дата в часовом поясе Алматы UTC+5. Жеребьёвка откладывается, если зарегистрировалось меньше шести.
- Не выкладывайте секреты, токены и реальные данные базы в GitHub. Не передавайте скриншоты базы с результатами.

## Обновление с v1 на v2 и восстановление
1. В существующем Supabase выполните `migration-v2.sql` **до** обновления кода. Не создавайте новую базу. Миграция архивирует и уже состоявшуюся жеребьёвку.
2. Замените файлы проекта и выполните redeploy. Не меняйте порядок, имена и пары участников после жеребьёвки.
3. Первая жеребьёвка записывается в отдельную таблицу `santa_first_draw` в той же транзакции, что и основное состояние. Триггер не позволяет обычному API заменить распределение, а при обновлении восстанавливает его из архива.
4. В админке доступен статус архива и кнопка восстановления. Она не запускает новую жеребьёвку и не показывает назначения.
5. Для защиты от удаления всего проекта отдельно сохраните приватную резервную копию базы (обе таблицы), например через pg_dump по инструкции Supabase. Не храните её в GitHub: она содержит персональные данные и результаты. Архив внутри той же БД не защищает от удаления всей БД.
6. После сброса профиля выдавайте доступ только его владельцу: имя само по себе не подтверждает личность.
